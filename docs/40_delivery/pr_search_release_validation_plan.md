# PR Search 릴리스 검증 계획

> 상태: review | 버전: v0.2 | 갱신일: 2026-08-19

## 1. 목적

릴리스 전 기능, 품질, 보안, 성능, 접근성, 운영 준비, 롤백 가능성을 검증한다. 화면 단위 검수 항목은 `../20_derived_ui_specs/pr_search_screen_qa_checklist.md`가 소유하며, 이 문서는 릴리스 수준의 게이트를 정의한다.

## 2. 검증 범위

| 영역 | 검증 방식 | 통과 기준 | 담당 |
| --- | --- | --- | --- |
| Requirements | 추적성 리뷰 | 릴리스에 포함된 모든 FR이 WP·테스트와 연결. 미커버 FR 0 | Product/QA |
| Frontend | 컴포넌트/E2E/접근성 | 상태 매트릭스 전 항목 렌더링, FLOW E2E 통과, axe 위반 0 | FE/QA |
| Backend/API | 단위/통합/계약 | API 계약 JSON 예시와 실제 응답 일치, 오류 코드 전수 검증 | BE/QA |
| Data | 마이그레이션/롤백/재구성 | up·down 무손실, 원본만으로 인덱스 전량 재구성 결과 동일 | BE/DBA |
| **정확성(도메인)** | 회귀 대조 | 시퀀스가 `git rev-list --first-parent`와 일치, SHA↔PR 매핑이 GHE와 일치 | BE/QA |
| Infra | 배포/롤백/DR | 롤백 10분 이내, 복구 훈련 통과 | Infra/SRE |
| Security | 권한 매트릭스/위협/시크릿/감사 | 비인가 노출 0, high risk 미해결 0, 시크릿 로그 노출 0 | Security |
| Performance | 부하 시험 | NFR-001·NFR-002 목표 달성 | BE/SRE |
| Accessibility | 자동 + 수동 | WCAG 2.1 AA, 키보드 전 경로, 대비 라이트·다크 | FE/QA |
| Observability | 대시보드/알림/런북 | 전 SLI 노출, 전 알림에 런북 연결, 런북 실행 가능 | SRE |

## 3. Release Gates

| Gate | 내용 | 통과 조건 | 적용 REL |
| --- | --- | --- | --- |
| Gate 1 | SRS/PRD/추적성 리뷰 | `validate_srs_prd_env.py --strict` 통과 또는 잔여 경고가 CR에 기록·수용됨. SRS 상태 `baseline` | 최초 1회 (착수 전) |
| Gate 2 | 아키텍처/ADR 리뷰 | 릴리스에 새 ADR이 필요한 결정이 있으면 기록·승인됨 | 전 REL |
| Gate 3 | 구현 테스트 스위트 | 릴리스에 포함된 전 WP의 DoD 통과, CI 전 항목 green | 전 REL |
| Gate 4 | 보안·개인정보 리뷰 | 권한 매트릭스 78셀 통과, 위협 모델 미완화 high 0, 시크릿 스캔 통과 | 전 REL |
| Gate 5 | 성능·접근성 리뷰 | 성능 목표 7종 달성, axe 위반 0, 대비 위반 0 | REL-002 이후 |
| Gate 6 | 운영 준비·롤백 리허설 | 런북 실행 확인, 롤백 10분 이내 실측, 대시보드·알림 구성 완료 | 전 REL |
| Gate 7 | **도메인 정확성 검증** | 회귀 검수 7종 통과 (QA 6장) | REL-003 이후 |

Gate 7은 이 제품 고유의 게이트다. 시퀀스와 매핑이 틀리면 다른 모든 품질 지표가 통과해도 제품이 잘못된 답을 준다.

## 6. 성능 검증

부하 시험은 합성 데이터셋(PR 100만, 커밋 1000만, 간선 2000만)에서 수행한다.

| ID | 항목 | 목표 | 방법 |
| --- | --- | --- | --- |
| QA-PERF-01 | 단건 식별자 해석 | p95 200ms | 대표 SHA·PR 번호 1000종 무작위 조회 |
| QA-PERF-02 | 필터 목록 조회 | p95 500ms | 대표 질의 20종 × 각 100회 |
| QA-PERF-03 | 시퀀스 범위 조회 | p95 400ms | 구간 5000건 조회 100회 |
| QA-PERF-04 | 집계 대시보드 | p95 1500ms | 그룹·시계열·백분위·분포 각 50회 |
| QA-PERF-05 | 화면 최초 콘텐츠 | p75 1.5초 | 사내망 브라우저 실측 |
| QA-PERF-06 | 동시 검색 세션 | 500 세션에서 위 목표 유지 | 부하 도구 |
| QA-PERF-07 | 수집 반영 지연 | p95 10초, p99 60초 | 이벤트 주입 후 검색 반영까지 측정 |
| QA-PERF-08 | 수신 버스트 흡수 | 60초간 2000 이벤트/초 유실 0 | 게이트웨이 부하 주입 |
| QA-PERF-09 | 재색인 소요 | 1000만 문서 4시간 이내 | 재색인 잡 실측 |
| QA-PERF-10 | 백필 중 실시간 지연 | 백필 3개 동시 실행 중 QA-PERF-07 유지 | 동시 실행 시험 |

QA-PERF-08과 QA-PERF-10은 이 제품 고유의 부하 특성을 검증한다. 웹훅은 평시에 조용하다가 대규모 머지 시 폭증하고, 백필은 장시간 자원을 점유한다. 평균 부하만 검증하면 실제 운영에서 무너진다.

## 7. 보안 검증

| 항목 | 방법 | 통과 기준 |
| --- | --- | --- |
| 권한 매트릭스 | 역할 6종 × 화면 13종 자동 테스트 | 78셀 전부 기대대로 |
| 접근 범위 강제 | 통합 테스트: 목록·건수·패싯·집계·상세 | 접근 범위 밖 데이터 0건 |
| 존재 여부 미노출 | 통합 테스트 | 접근 범위 밖 직접 조회가 404 |
| 강제 필터 우회 | 아키텍처 테스트 + 타입 검사 | 우회 경로 컴파일 실패 |
| 웹훅 서명 | 단위 테스트 (유효·무효·변조·누락) | 미검증 처리 0건 |
| 매핑 화이트리스트 | 매핑 검사 | `dynamic: strict` 전 인덱스 적용 |
| 시크릿 노출 | 로그 스캔 | 토큰·시크릿 0건 |
| 세션 쿠키 속성 | E2E 헤더 검사 | HttpOnly·Secure·SameSite 확인 |
| 권한 캐시 무효화 | 통합 테스트 | 회수 후 첫 요청 차단 |
| 저장된 검색 권한 | 통합 테스트 | 저장자 권한 미승계 확인 |
| 위협 모델 | 리뷰 | THR-001~020 완화 확인, 미완화 high 0 |
| 의존성 취약점 | 자동 스캔 | high 이상 0 (또는 예외 승인 기록) |

## 8. 도메인 정확성 검증 (Gate 7)

이 제품의 존재 이유가 "정확한 순서와 정확한 매핑"이므로, 별도 게이트로 다룬다.

| ID | 항목 | 방법 | 통과 기준 |
| --- | --- | --- | --- |
| ACC-01 | 시퀀스 안정성 | 이전 릴리스와 시퀀스 값 대조 | 에폭 변경이 없었다면 전부 동일 |
| ACC-02 | 시퀀스-git 일치 | `git rev-list --first-parent --reverse`와 대조 | 순서·구성 완전 일치 |
| ACC-03 | 범위 조회-git 일치 | `git log --first-parent <tagA>..<tagB>`와 대조 | 건수·구성 완전 일치 |
| ACC-04 | SHA→PR 매핑 | 표본 100건을 GHE 실제 값과 대조 | 100% 일치 |
| ACC-05 | PR→머지 커밋 매핑 | 표본 50건을 GHE 실제 값과 대조 | 100% 일치 |
| ACC-06 | 관계 정확도 | 되돌림·체리픽 표본 200건 수동 검수 | 95% 이상 정확, 신뢰도 표기 정확 |
| ACC-07 | 재색인 동일성 | 재색인 전후 검색 결과 대조 | 완전 일치 |
| ACC-08 | 원본 재구성 동일성 | `raw_event`만으로 인덱스 재구성 후 대조 | 완전 일치 |

**회귀 픽스처**: 합성 저장소에 다음을 포함한 히스토리를 만들어 CI에서 반복 검증한다.

- 일반 squash merge 연속
- PR을 거치지 않은 직접 푸시
- 대상 브랜치 강제 푸시 (재작성)
- 릴리스 브랜치로의 체리픽
- 되돌림 커밋과 되돌림의 되돌림
- 병합 커밋 정책 저장소 (가정 5.1.1 위반 감지용)
- 태그가 여러 커밋에 걸친 릴리스

ACC-06(관계 정확도)은 REL-004의 exit criteria이자 OD-007(W-007 활성화 여부) 판단 근거다.

## 9. Rollout / Rollback

### 롤아웃 전략

| REL | 전략 | 대상 |
| --- | --- | --- |
| REL-001 | 파일럿 저장소 3개, 실시간 수집만 | 개발팀 |
| REL-002 | 파일럿 저장소 백필 + 베타 사용자 10명 | 개발팀 + 초기 사용자 |
| REL-003 | 핵심 저장소 30개로 확대, 베타 공개 | 개발자 + 릴리스 매니저 |
| REL-004 | 사용자 확대 | 전 개발 조직 |
| REL-005 | 전체 저장소 등록 시작 (점진 백필) | 전 조직 + 관리자 |
| REL-006 | 전체 공개 | 전사 |

기능 플래그: `W-007 관계 그래프`, `이분 탐색`, `안전 구간 표식`, `내보내기`를 플래그로 제어해 문제 시 즉시 비활성화한다. 파이프라인·시퀀스는 플래그로 끄지 않는다 (데이터 일관성 훼손).

### 마이그레이션 순서

1. PostgreSQL 마이그레이션 (하위 호환)
2. Elasticsearch 매핑 변경 필요 시 재색인 잡 (별칭 미전환 상태로 준비)
3. 워커 배포
4. `search-api` 배포
5. `web` 배포
6. 별칭 전환 (재색인이 있었던 경우)

### 롤백 트리거

| 트리거 | 조치 |
| --- | --- |
| 배포 후 5분 내 오류율 5% 초과 | 자동 롤백 |
| 수집 지연 p95가 60초 초과 15분 지속 | 워커만 롤백 |
| 권한 관련 결함 발견 | 즉시 전체 롤백 (보안 우선) |
| 시퀀스 값 불일치 발견 | 즉시 워커 롤백 + 정합성 점검 |
| 검색 p95가 목표의 2배 초과 | `search-api` 롤백 |

롤백 담당: 배포 승인자(당번 SRE). 롤백 결정에 승인을 기다리지 않는다.

### 사용자 소통

- P1 장애·저하 모드: 화면 배너 + 사내 채널 즉시 공지
- 시퀀스 재채번: 영향받는 저장소 사용자에게 알림 (과거 범위 인용 무효 안내)
- 계획 정비: 24시간 전 공지

## 10. Release Signoff

| Role | Signoff Criteria | Status |
| --- | --- | --- |
| Product | 범위 수용, 미구현 항목이 Known Limitations에 기록됨 | pending |
