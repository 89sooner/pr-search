# PR Search 릴리스 검증 계획

> 상태: review | 버전: v0.7 | 갱신일: 2026-09-08

## 1. 목적

릴리스 전 기능, 품질, 보안, 성능, 접근성, 운영 준비, 롤백 가능성을 검증한다. 화면 단위 검수 항목은 `../20_derived_ui_specs/pr_search_screen_qa_checklist.md`가 소유하며, 이 문서는 릴리스 수준의 게이트를 정의한다.

### 3.1 배포 프로파일과 게이트 판정 (CR-059 / ADR-021)

**게이트 판정은 배포 프로파일에 따라 무엇을 증명할 수 있는지가 다르다.** 첫 사내 파일럿의 Profile A는 단일 호스트이고 외부망에는 사내 환경이 없으므로, **외부에서 증명 가능한 것과 사내에서만 증명 가능한 것을 반드시 가른다.**

| 판정 | 뜻 |
| --- | --- |
| `VERIFIED (external)` | 외부망에서 **실제로 실행해** 통과했다 |
| `NOT RUN — internal environment required` | 사내 환경이 있어야 실행 가능하다. **합성으로 통과시키지 않는다** |
| `NOT APPLICABLE (Profile A)` | 그 형상에서 성립하지 않는 항목이다 (예: 롤링 업데이트 무중단) |

외부망에서 **증명할 수 없는 것**은 다음과 같으며, 이 목록에 있는 항목을 외부 실행 결과로 통과시키는 것을 금지한다.

- 실제 사내 GHE App·웹훅·저장소 권한, 실제 사내 OIDC와 그룹 클레임
- 사내 CA·프록시·DNS, 사내 컨테이너 레지스트리, 사내 보안 스캔
- 실제 서버의 CPU·RAM·디스크, 실데이터 규모의 성능, 실제 롤백 소요
- `ACC-06`(관계 간선 정확도 표본 200건 검수) — **합성 GHE 데이터로 95%를 만들어 내지 않는다.** 그것이 성립하지 않으므로 `W-007`·`WP-043`은 계속 `NOT ACTIVATED`다

**Gate 6의 롤백 10분은 Profile A에도 그대로 적용된다** (CR-060, DEV-505). 이전 판은 그것을 "무중단 롤링 업데이트를 전제한다"며 판정 대상에서 뺐는데, **`NFR-008`의 그 지표는 무중단을 요구한 적이 없다** — 비고 칸이 이미 "이전 이미지 재배포"라고 적고 있고 그것이 정확히 Profile A가 하는 일이다. `CR-059`가 만든 예외는 `NFR-004`의 가용성 백분율과 RTO 30분에 한정되며, **그것으로 별개 요구사항인 `NFR-008`을 면제할 수 없다.** 파생 문서가 승인 범위를 좁히는 것도 넓히는 것과 같은 위반이다.

Profile A의 롤백은 `.env`의 `PRS_VERSION`을 이전 값으로 되돌리고 `prsctl upgrade`를 다시 실행하는 것이며, **그 소요를 실측해 10분 목표로 판정한다.** 짧은 중단이 생기는 것은 사실이나 그것은 `NFR-004`의 가용성 지표가 다룰 문제이지 롤백 소요 목표를 바꾸지 않는다.

## 8. 도메인 정확성 검증 (Gate 7)

이 제품의 존재 이유가 "정확한 순서와 정확한 매핑"이므로, 별도 게이트로 다룬다.

| ID | 항목 | 방법 | 통과 기준 | 자동화 |
| --- | --- | --- | --- | --- |
| ACC-01 | 시퀀스 안정성 | 이전 릴리스와 시퀀스 값 대조 | 에폭 변경이 없었다면 전부 동일 | 미자동화 |
| ACC-02 | 시퀀스-git 일치 | `git rev-list --first-parent --reverse`와 대조 | 순서·구성 완전 일치 | **자동화 완료 (WP-021)** — `regression/sequence.test.ts` |
| ACC-03 | 범위 조회-git 일치 | `git log --first-parent <tagA>..<tagB>`와 대조 | 건수·구성 완전 일치 | 미자동화 — WP-023(범위 조회 API)이 채운다 |
| ACC-04 | SHA→PR 매핑 | 표본 100건을 GHE 실제 값과 대조 | 100% 일치 | 미자동화 |
| ACC-05 | PR→머지 커밋 매핑 | 표본 50건을 GHE 실제 값과 대조 | 100% 일치 | 미자동화 |
| ACC-06 | 관계 정확도 | 되돌림·체리픽 표본 200건 수동 검수 | 95% 이상 정확, 신뢰도 표기 정확 | 수동 검수 (표본 200건) — **NOT RUN (2026-08-29)**: 검수 가능한 실제 표본이 없다. 합성 픽스처로 숫자를 만들지 않는다 (원장 6.46장) |
| ACC-07 | 재색인 동일성 | 재색인 전후 검색 결과 대조 | 완전 일치 | 미자동화 — WP-034(재색인)가 채운다 |
| ACC-08 | 원본 재구성 동일성 | `raw_event`만으로 인덱스 재구성 후 대조 | 완전 일치 | 미자동화 |

**회귀 픽스처**: 합성 저장소에 다음을 포함한 히스토리를 만들어 CI에서 반복 검증한다.

- 일반 squash merge 연속
- PR을 거치지 않은 직접 푸시
- 대상 브랜치 강제 푸시 (재작성)
- 릴리스 브랜치로의 체리픽
- 되돌림 커밋과 되돌림의 되돌림
- 병합 커밋 정책 저장소 (가정 5.1.1 위반 감지용)
- 태그가 여러 커밋에 걸친 릴리스

ACC-06(관계 정확도)은 REL-004의 exit criteria이자 W-007(관계 그래프 화면) 활성화 여부의 판단 근거다. 표본 200건 검수에서 95% 이상이면 W-007과 WP-043을 착수하고, 미달이면 관계를 목록 형태로만 제공한다 (SRS 4.2 조건부 범위).

**(2026-08-29 판정) ACC-06 = NOT RUN → W-007·WP-043 NOT ACTIVATED.** 이 환경에 검수 가능한 실제
관계 표본이 없다 — `prs-links` 1건, `prs-pull-requests`·`prs-commits`·PostgreSQL 정본 전부 0건이며,
대체 표본 후보인 이 저장소 자체에도 되돌림·체리픽 커밋이 0건이다 (원장 6.46장). **미달이 아니라
측정하지 못한 것이므로 활성화 조건이 성립하지 않는다.** 합성 픽스처로 200건을 채워 95%를
계산하지 않는다 — 그 숫자는 우리가 만든 규칙이 우리가 만든 데이터에서 동작한다는 뜻일 뿐,
ACC-06이 묻는 "실제 저장소의 관계를 사람이 보았을 때 맞는가"에 답하지 않는다.

### 10.4 조합 시험 원칙

flag가 N개면 조합은 2^N로 폭발한다. 전 조합 실행은 하지 않는다. 대신:

```text
스키마·제약 검증        모든 유효 조합을 스키마가 표현할 수 있는가
속성 기반 시험          무작위 조합에서 제약이 항상 지켜지는가
페어와이즈 조합 시험    두 flag 쌍의 상호작용
핵심 워크플로 시나리오  실제 업무 경로
전 command/flag 분류 감사  빠진 것이 없는가
```

"모든 조합 지원"의 정의는 NFR-009와 같다 — 유효한 모든 조합을 스키마가 표현할 수 있다는 뜻이다. CR-008에서 그 검증 수단을 인벤토리 커버리지·스키마 검증·제약 속성 시험·유효/무효 조합 생성기·페어와이즈 조합 시험·핵심 워크플로 시나리오·golden argv 시험 일곱 가지로 못 박았다 (WP-065).
