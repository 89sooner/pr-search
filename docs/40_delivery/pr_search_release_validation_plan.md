# PR Search 릴리스 검증 계획

> CR-097 / WP-085: FR-SRC-001~004 게이트는 Source API 인증/범위/입력/응답 no-store·감사 메타데이터, SHA 고정·rename·이동 PR·binary/크기 제한, Tree→History→Diff→Time-lapse 브라우저 흐름, 영어·테마·키보드·모달 접근성 검사다. 목 기반 로컬 통과를 실제 사내 GHE 권한·버전 검증으로 대체하지 않는다. 이번 작업은 릴리스 발행을 포함하지 않는다.

> 상태: review | 버전: v0.14 | 갱신일: 2026-09-17

## CR-102 Regression 확장 수용안

승인 전 검증 설계는 [구현 계획 8장](pr_search_regression_implementation_plan.md#8-검증-시나리오와-실행-명령) T01~T12가 소유한다. dense/sparse·직접 커밋·SKIP/INCONCLUSIVE 경계 보존·ambiguous·epoch·동시성/멱등·권한·artifact SHA/variant·pending·coarse/fine·MTBF·migration/rollback·접근성·실측 pilot을 검증한다. R0 이후 승인 FR/WP와 QA 체크리스트에 옮긴다. 원인 후보를 binary 가용성만으로 지워 단일 결과를 만드는 동작은 실패다. 사내 pilot은 실제 시험 증거와 후보 선택/binary 검색 시간의 전후 측정이 필요하며, fixture 통과나 이상적 log2 횟수로 대체하지 않는다. 이번 요청에서 앱 시험·배포·사내 시험은 수행하지 않았다.

CR-079: WP-074의 수용 시험은 [실행서](pr_search_wp074_execution.md) T01~T06·변이 목록이 정본이다. migration 왕복·실제 DB/ES/Redis/git·인증 세션 UI·이미지 런타임·read-only 측정 CLI가 필요하다. 단계별 상태를 계약 정정/구현/외부 실제 실행/사내 운영/WP-075로 구분한다. 직접 부재 증거 한계를 seed fixture로 숨기지 않는다. 이번 설계 세션에서 앱 시험과 후보 번들은 NOT RUN이다.

### 3.1 배포 프로파일과 게이트 판정 (CR-059 / ADR-021)

**게이트 판정은 배포 프로파일에 따라 무엇을 증명할 수 있는지가 다르다.** 첫 사내 파일럿의 Profile A는 단일 호스트이고 외부망에는 사내 환경이 없으므로, **외부에서 증명 가능한 것과 사내에서만 증명 가능한 것을 반드시 가른다.**

| 판정 | 뜻 |
| --- | --- |
| `VERIFIED (external)` | 외부망에서 **실제로 실행해** 통과했다 |
| `NOT RUN — internal environment required` | 사내 환경이 있어야 실행 가능하다. **합성으로 통과시키지 않는다** |
| `NOT APPLICABLE (Profile A)` | 그 형상에서 성립하지 않는 항목이다 (예: 롤링 업데이트 무중단) |

외부망에서 **증명할 수 없는 것**은 다음과 같으며, 이 목록에 있는 항목을 외부 실행 결과로 통과시키는 것을 금지한다.

- 실제 사내 GHE App·웹훅·저장소 권한, 실제 사내 OIDC와 그룹 클레임
- 사내 CA·프록시·DNS, 사내 컨테이너 레지스트리, 사내 보안 스캔
- 실제 서버의 CPU·RAM·디스크, 실데이터 규모의 성능, 실제 롤백 소요
- `ACC-06`(관계 간선 정확도 표본 200건 검수) — **합성 GHE 데이터로 95%를 만들어 내지 않는다.** 그것이 성립하지 않으므로 `W-007`·`WP-043`은 계속 `NOT ACTIVATED`다

**Gate 6의 롤백 10분은 Profile A에도 그대로 적용된다** (CR-060, DEV-505). 이전 판은 그것을 "무중단 롤링 업데이트를 전제한다"며 판정 대상에서 뺐는데, **`NFR-008`의 그 지표는 무중단을 요구한 적이 없다** — 비고 칸이 이미 "이전 이미지 재배포"라고 적고 있고 그것이 정확히 Profile A가 하는 일이다. `CR-059`가 만든 예외는 `NFR-004`의 가용성 백분율과 RTO 30분에 한정되며, **그것으로 별개 요구사항인 `NFR-008`을 면제할 수 없다.** 파생 문서가 승인 범위를 좁히는 것도 넓히는 것과 같은 위반이다.

Profile A의 롤백은 `.env`의 `PRS_VERSION`을 이전 값으로 되돌리고 `prsctl upgrade`를 다시 실행하는 것이며, **그 소요를 실측해 10분 목표로 판정한다.** 짧은 중단이 생기는 것은 사실이나 그것은 `NFR-004`의 가용성 지표가 다룰 문제이지 롤백 소요 목표를 바꾸지 않는다.

**회귀 픽스처**: 합성 저장소에 다음을 포함한 히스토리를 만들어 CI에서 반복 검증한다.

- 일반 squash merge 연속
- PR을 거치지 않은 직접 푸시
- 대상 브랜치 강제 푸시 (재작성)
- 릴리스 브랜치로의 체리픽
- 되돌림 커밋과 되돌림의 되돌림
- 병합 커밋 정책 저장소 (가정 5.1.1 위반 감지용)
- 태그가 여러 커밋에 걸친 릴리스

ACC-06(관계 정확도)은 REL-004의 exit criteria이자 W-007(관계 그래프 화면) 활성화 여부의 판단 근거다. 표본 200건 검수에서 95% 이상이면 W-007과 WP-043을 착수하고, 미달이면 관계를 목록 형태로만 제공한다 (SRS 4.2 조건부 범위).

**(2026-08-29 판정) ACC-06 = NOT RUN → W-007·WP-043 NOT ACTIVATED.** 이 환경에 검수 가능한 실제
관계 표본이 없다 — `prs-links` 1건, `prs-pull-requests`·`prs-commits`·PostgreSQL 정본 전부 0건이며,
대체 표본 후보인 이 저장소 자체에도 되돌림·체리픽 커밋이 0건이다 (원장 6.46장). **미달이 아니라
측정하지 못한 것이므로 활성화 조건이 성립하지 않는다.** 합성 픽스처로 200건을 채워 95%를
계산하지 않는다 — 그 숫자는 우리가 만든 규칙이 우리가 만든 데이터에서 동작한다는 뜻일 뿐,
ACC-06이 묻는 "실제 저장소의 관계를 사람이 보았을 때 맞는가"에 답하지 않는다.

flag가 N개면 조합은 2^N로 폭발한다. 전 조합 실행은 하지 않는다. 대신:

```text
스키마·제약 검증        모든 유효 조합을 스키마가 표현할 수 있는가
속성 기반 시험          무작위 조합에서 제약이 항상 지켜지는가
페어와이즈 조합 시험    두 flag 쌍의 상호작용
핵심 워크플로 시나리오  실제 업무 경로
전 command/flag 분류 감사  빠진 것이 없는가
```

"모든 조합 지원"의 정의는 NFR-009와 같다 — 유효한 모든 조합을 스키마가 표현할 수 있다는 뜻이다. CR-008에서 그 검증 수단을 인벤토리 커버리지·스키마 검증·제약 속성 시험·유효/무효 조합 생성기·페어와이즈 조합 시험·핵심 워크플로 시나리오·golden argv 시험 일곱 가지로 못 박았다 (WP-065).


## WP-073 UI 품질 검증 (CR-067)

기존 API·인가·데이터·인프라·보안·운영 릴리스 게이트를 유지한다. 이 패키지의 추가 검증은 `workbench.spec.ts`의 키보드/URL/요청 수/뷰포트/브라우저 axe와 전체 기존 e2e/a11y/contrast·타입·린트·프로덕션 빌드다. UI fixture 검증은 사내 IdP/GHE 통합 승인이나 제품 전체 릴리스 승인을 뜻하지 않는다. 되돌림 단위는 WP-073의 웹 표현/문서 변경이며 데이터 마이그레이션은 없다.

## M 넘버 검증 (WP-074·WP-075, CR-077)

`FR-SEQ-008`(채번)·`FR-SEQ-009`(표기)의 검증 항목이다. 새 `ACC`·`GATE` ID는 만들지 않는다: `CR-077`이 승인한 ID 목록에 이 문서 몫의 신규 ID가 없다. 아래 첫 항목은 `ACC-02`(시퀀스-git 일치, 8장)와 같은 회귀 방식을 재사용한다.

| 항목 | 방법 | 통과 기준 |
| --- | --- | --- |
| M 넘버 순서 정합성 | `git log --first-parent`에서 PR 머지 커밋만 추려낸 순서와 M 넘버 오름차순을 대조한다(`ACC-02`와 같은 방식) | 순서와 구성이 완전히 일치한다 |
| 직접 푸시 배제 | 직접 푸시가 섞인 회귀 픽스처에서 채번을 실행한다 | 직접 푸시 커밋은 M 넘버를 받지 않고, 번호를 소비하지도 않는다(`FR-SEQ-008` AC-1) |
| 채번 멱등성 | 같은 구간에 채번을 재실행한다 | 기존에 부여된 M 넘버 값이 모두 그대로 유지된다(`FR-SEQ-008` AC-7) |
| 표기 멱등성 | 이미 `[M-...]` 접두가 붙은 PR 제목에 표기 잡을 재실행한다 | 제목을 다시 쓰지 않는다(`FR-SEQ-009` AC-2) |

`DEV-576`이 해소되기 전에는 채번이 최대 6시간 보정 스윕에 의존한다. 이 표의 검증 자체는 그 상태에서도 유효하지만, 회의가 요구한 "거의 실시간" 전제는 `DEV-576` 해소 전까지 성립하지 않는다(로드맵 4.2장).
