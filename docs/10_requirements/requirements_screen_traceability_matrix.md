# 요구사항-화면 추적 매트릭스

> 상태: review | 버전: v0.9 | 갱신일: 2026-08-28

## 1. 목적

본 문서는 `srs_final.md`의 요구사항 ID를 `pr_search_*` 파생 문서군의 화면 ID와 연결한다.

## 2. 사용 원칙

1. 기능 기준은 `srs_final.md`다.
2. 화면 ID 기준은 `../20_derived_ui_specs/pr_search_product_ia.md`와 `../20_derived_ui_specs/pr_search_wireframe_spec.md`다.
3. 하나의 요구사항은 하나 이상의 화면 ID와 연결될 수 있다.
4. UI가 직접 없는 요구사항도 관리자, 설정, 감사, 상태 화면 등 간접 노출 지점으로 연결한다.
5. 승인된 모든 FR은 이 매트릭스에 나타나야 한다. 어디에도 노출되지 않는 FR은 근거를 비고에 남긴다.

## 3. 화면군 요약

사용자 화면 (`W-###`):

- `W-001` 통합 검색 — 옴니 입력, 결과 목록, 필터 레일, 패싯
- `W-002` PR 상세 — 개요, 커밋, 관계, 선행·후행, 포함 릴리스, 타임라인
- `W-003` 커밋 상세 — 소속 PR, 시퀀스 위치, 포함 릴리스, 관계
- `W-004` 범위 조사 — 앵커 지정, 구간 PR 목록, 요약 통계, 안전 구간 표식, 이분 탐색
- `W-005` 릴리스·빌드 — 릴리스 타임라인, 릴리스 상세, 구간 비교 진입
- `W-006` 통계 대시보드 — 그룹 집계, 시계열, 백분위, 분포
- `W-007` 관계 그래프 — 노드·간선 시각화, 깊이·유형 필터
- `W-008` 저장된 검색 — 두 논리 목록(내 검색 · 팀 공유), 생성·편집, 공개 범위와 대상 팀 (CR-049)
- `W-009` 저장소 개요 — 저장소 카드, 시퀀스 공간 상태, 수집 상태

관리자 화면 (`A-###`):

- `A-001` 수집 파이프라인 콘솔 — 단계별 지표, 실패 대기열, 조정 스캔 결과
- `A-002` 저장소 등록 관리 — 등록·해제, 시퀀스 대상 브랜치, 미러 설정
- `A-003` 인덱스·잡 운영 — 백필, 재색인, 시퀀스 채번·정합성 점검, 잡 진행률
- `A-004` 감사 로그 — 감사 기록 조회·필터

## 6. 검증 메모

- 모든 요구사항 ID는 `srs_final.md` 또는 `prd.md`에 존재해야 한다.
- 모든 화면 ID는 IA 또는 wireframe 문서에 존재해야 한다.
- validator가 미커버 FR과 미선언 화면 ID를 보고한다.
- 간접 노출로 표시한 요구사항은 반드시 "관련 화면 ID"에 최소 1개 화면을 지정한다. 어디에도 노출되지 않는 요구사항은 이 문서에 존재할 수 없다.
- **SRS 버전이 오르면 이 문서를 같은 pass에서 다시 본다** (`10_requirements/AGENTS.md`). 매핑이 바뀌지 않아도 대조했다는 사실을 헤더 갱신으로 남긴다 — 그러지 않으면 "아직 안 봤다"와 "봤고 그대로다"가 구분되지 않는다.

**SRS v2.8 (CR-044, 2026-08-26) 대조 결과: 매핑 변경 0건.** FR-SEQ-002 AC-7의 봉인 값 정의가 정정됐을 뿐 요구사항의 노출 화면도 소유도 바뀌지 않았다 — W-004가 주요 화면이고 W-001·W-005가 관련 화면인 것은 그대로다. 신규 FR·NFR이 없으므로 5장 커버리지 요약(76종)도 그대로다. 두 축을 다시 셌고 여전히 일치한다.

**SRS v2.7 (CR-043, 2026-08-26) 대조 결과: 매핑 변경 3건 — 전부 이미 있던 사실을 적은 것이다.** FR-SRCH-009에 W-004를 더했고(와이어프레임 `W-004-FACETS`와 WP-032가 이미 요구하던 것을 SRS가 승인했다), FR-SEQ-002에 커서·패싯 소유를 명시했으며, FR-SRCH-008에서 W-004를 뗐다. **셋째가 이 pass의 소득이다** — 매트릭스는 W-004의 커서를 FR-SRCH-008에 걸고 있었는데 그 요구사항의 SRS 관련 화면은 W-001뿐이었고, 무엇보다 두 화면은 순회하는 정본이 다르다. 기능은 그대로 남고 소유만 FR-SEQ-002(Must)로 옮겼다 — FR-SRCH-008은 Should이므로 소유가 옮겨지며 오히려 강해졌다. 신규 FR·NFR이 없으므로 5장 커버리지 요약(76종)은 그대로다. 두 축을 다시 셌고 FR 정의 수와 매트릭스 매핑 수가 여전히 일치한다.

**SRS v2.6 (CR-040, 2026-08-26) 대조 결과: 매핑 변경 0건.** OD-005 결정은 FR-SRCH-011의 **구현 경로**(분석기 구성)를 고른 것이고 수용 기준·노출 화면은 바뀌지 않았다. 신규 FR·NFR이 없으므로 5장 커버리지 요약(76종)도 그대로다. 두 축을 다시 셌다 — FR 정의 수와 매트릭스 매핑 수가 여전히 일치한다.
