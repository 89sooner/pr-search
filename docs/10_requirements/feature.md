# PR Search 기능 후보 문서

> 상태: review | 버전: v0.2 | 갱신일: 2026-08-19

## 1. 목적

이 문서는 PR Search의 후보 기능을 수집하고 정규화한다. 이 문서는 승인된 범위가 아니며, `srs_final.md` 또는 `prd.md`에 반영된 항목만 구현 범위가 된다. 후보가 승인되면 상태를 갱신하고 관련 FR ID를 기록한다.

수집 출처:

| 출처 ID | 출처 | 내용 요약 |
| --- | --- | --- |
| SRC-01 | 사내 형상관리 전환 인터뷰 (Perforce → GitHub Enterprise) | P4 Changelist(CL) 번호는 submit 시점 채번이라 `번호 순서 = 반영 순서`가 보장되었으나, GitHub PR 번호는 생성 시점 채번이라 머지 순서와 불일치한다. 이 때문에 "CL 12000~12500 구간 조사" 같은 범위 기반 조사 관행이 깨졌다. |
| SRC-02 | 조직 관리자 요구 | 배포/빌드 단위로 "무엇이 들어갔는가"를 즉시 확인하고 싶다. GitHub UI 검색은 학습 비용이 크다. |
| SRC-03 | 개발자 요구 | 장애 커밋 SHA만 손에 쥔 상태에서 그 SHA를 만든 PR·리뷰어·이슈를 역추적하고 싶다. 반대로 PR 번호에서 실제 반영 커밋을 찾고 싶다. |
| SRC-04 | 운영 정책 | PR은 Squash & Merge 단일 정책이며 1 PR = target 브랜치 1 커밋이다. GitHub Enterprise 웹훅을 사내 앱이 이미 구독 중이다. |
| SRC-05 | 기술 방향 지시 | 저장/검색은 Elasticsearch를 축으로 하고, 대시보드는 사내 `design-system`(Conductor)을 사용하며, 구현 언어는 TypeScript로 통일한다. |
