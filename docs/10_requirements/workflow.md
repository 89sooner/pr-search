# PR Search SRS 작성 워크플로

> 상태: review | 버전: v0.2 | 갱신일: 2026-08-19

## 1. 목적

이 문서는 PR Search의 요구사항을 후보 기능에서 최종 SRS까지 정제하는 절차를 정의한다.

## 2. 단계

1. 분석 범위 정의
2. 소스 수집 및 분석 기준 수립
3. 기능 인벤토리 작성
4. 기능 클러스터링 및 정보 구조 정리
5. 도메인 용어 정의 (`glossary.md`)
6. 사용자 시나리오 및 업무 흐름 도출
7. 구현/운영 대응성 검토
8. 비기능 요구사항 및 제약 정의
9. SRS 초안 작성
10. 검토, 우선순위화, 확정(baseline)

## 3. 기능 분석 필드

- 기능 ID
- 사용자 목표
- 출처/근거
- 진입 화면 또는 트리거
- 주요 액션
- 시스템 반응
- 예외 상황
- 데이터 모델 영향
- 권한 및 감사 요구
- 실현 방식
- 릴리스 후보

## 4. 추적 구조

소스 문서 ID -> 기능 ID -> 시나리오 ID -> 요구사항 ID -> 화면 ID -> WP ID -> QA 항목 -> 코드/테스트

## 5. SRS 작성 원칙

- 기능 요구사항은 고유 요구사항 ID와 전체 블록(출처, 수용 기준, 검증 방법, 관련 ID)을 가진다.
- 요구사항 문장은 EARS 패턴(상시/이벤트/상태/예외/선택) 중 하나를 따른다.
- 검증 가능한 문장으로 작성한다. 빠르게/쉽게/적절히 같은 비계량 표현은 수치로 대체한다.
- UI 설명과 시스템 행위를 구분한다. 배치·문구는 파생 UI 문서의 몫이다.
- 제외 범위와 조건부 범위를 명시한다.
- 미확정 사항은 가정 또는 오픈 결정(`OD-###`)으로 남기고 임의로 확정하지 않는다.
