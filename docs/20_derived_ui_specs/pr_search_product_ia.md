## 0. 현재 문서 세트와 사용 순서

이 문서는 `docs/20_derived_ui_specs/`의 최상위 IA 기준 문서다. 제품 범위를 새로 정하지 않으며 `../10_requirements/srs_final.md`와 `../10_requirements/prd.md`의 승인 범위를 화면 구조로 번역한다. 이 문서에서 선언한 화면 ID만 하위 문서(와이어프레임, 플로우, 상태 매트릭스, 컴포넌트, QA)에서 사용할 수 있다.

## 2. IA 설계 원칙

1. **식별자 우선(Identifier-first)**: 사용자가 손에 쥔 문자열(SHA, PR 번호, URL, 태그)을 어디에 붙여넣어야 할지 고민하지 않도록, 단일 옴니 입력을 전역 상단에 상시 노출한다. 검색은 화면이 아니라 셸의 일부다.
2. **조사 경로의 연속성**: 조사는 "무언가 하나를 찾고 → 그 주변을 본다"의 반복이다. 모든 상세 화면은 다음 조사 단계(선행·후행, 포함 릴리스, 관계, 범위 조사)로 이어지는 진입점을 화면 안에 둔다. 사용자가 검색으로 되돌아가 다시 시작하게 만들지 않는다.
3. **순서 축의 상시 표시**: 머지 시퀀스는 이 제품의 존재 이유다. PR·커밋을 표시하는 모든 표면에 시퀀스 값과 시퀀스 공간(저장소·브랜치)을 함께 노출한다.
4. **점진적 공개**: 상세 화면은 개요 → 커밋 → 관계 → 타임라인 순으로 섹션을 나누고, **자기 문서 밖을 부르는 섹션은 사용자가 열 때 조회한다** — 관계 그래프, 동시 변경, 포함 릴리스, 선행·후행이 그렇다 (CR-031, DEV-162). 진입 시 요청은 **그 화면의 주 문서 하나**이며, 이것은 WP-017이 시험으로 건 규율이다.
5. **복구 가능성 우선**: 빈 결과, 권한 없음, 보강 미완료, 시퀀스 재채번 중 등 모든 비정상 상태는 원인과 다음 행동을 함께 표시한다.
6. **권한·수집 상태의 명시적 노출**: "결과가 없음"과 "권한이 없음"과 "아직 수집되지 않음"은 서로 다른 상태이며 화면에서 구분해 표시한다.

두 Plane은 셸에서 분리된 영역으로 표현한다. Search Workspace의 화면은 읽기 전용 파생 데이터를 보여주고, GitHub Operations의 화면은 실제 GitHub 상태를 바꾼다. 사용자가 지금 어느 쪽에 있는지 헷갈리면 안 되므로, Operations 영역은 인증된 GitHub 신원과 대상 호스트를 항상 표시한다.

전역 셸 구조 (`AppShell`):

```text
┌──────────────────────────────────────────────────────────────┐
│ TopBar: [제품명] [옴니 검색 입력 ⌘K] [시퀀스 공간 선택] [사용자]│
├──────────┬───────────────────────────────────────────────────┤
│ NavList  │ Main (라우트별 화면)                              │
│  검색    │                                                   │
│  범위조사│                                                   │
│  릴리스  │                                                   │
│  통계    │                                                   │
│  저장검색│                                                   │
│  저장소  │                                                   │
│  ─────   │                                                   │
│  운영 ▾  │                                                   │
└──────────┴───────────────────────────────────────────────────┘
```

- TopBar의 옴니 검색은 모든 화면에서 상시 노출되며 `⌘K`/`Ctrl+K`로 포커스한다.
- 좌측 내비게이션의 "운영" 그룹은 `operator` 또는 `security_officer` 역할에게만 표시한다.
- 시퀀스 공간 선택기는 W-002·W-003·W-004·W-005에서 현재 컨텍스트를 표시하고, W-001·W-006에서는 필터로 동작한다.

## 6. 화면 ID 체계

- `W-###`: 일반 사용자 웹 화면. 100 단위 그룹을 두지 않고 001부터 순차 부여한다.
- `A-###`: 관리자 콘솔 화면.
- `D-###`: 사용하지 않는다. 이 제품은 데스크톱 앱 표면이 없다.
- 화면 안의 하위 영역은 `W-002-COMMITS`처럼 화면 ID에 영역 접미사를 붙여 참조한다. 새 화면 ID를 만들지 않는다.
- 화면 ID는 안정 식별자다. 화면이 제거되면 표에서 `deprecated`로 표시하고 번호를 재사용하지 않는다.

## P4 작업대 배치 정밀화 (CR-067 / WP-073)

FR-SRCH-001·006~011, FR-SEQ-001·005, NFR-007을 근거로 기존 화면 계층을 유지하며 공통 셸의 제품 탐색과 작업 영역을 구분한다. 왼쪽은 역할에 따라 걸러진 작업별 내비게이션, 상단은 현재 화면 맥락·빠른 검색, 본문은 해당 조사다. W-001 안에서 필터 → 결과 → 선택 요약을 연결한다. 선택 요약은 C-013의 보조 표현이며 새 화면·새 API가 아니다. 루트는 검색/범위/저장소/저장된 검색의 진입점을 제공하며 인증 미구성 상태를 별도로 설명한다.
