# PR Search 와이어프레임 사양서

> 상태: review | 버전: v0.2 | 갱신일: 2026-08-19

## 0. 문서 위치와 책임

이 문서는 화면별 목적, 진입 경로, 레이아웃, 섹션, 컴포넌트, 상태, 이벤트, 권한/정책을 정의한다. 화면 ID는 `pr_search_product_ia.md`에서 선언한 것만 사용한다. 상태 이름은 `pr_search_screen_state_matrix.md`의 공통 상태 분류를 따른다. 컴포넌트 ID는 `pr_search_ui_component_spec.md`에서 정의한다.

## 1. 공통 화면 사양 형식

각 화면은 다음 순서를 따른다.

- 화면 목적
- 진입 경로
- 레이아웃 구조
- 섹션 정의
- 주요 컴포넌트
- 상태 정의
- 이벤트 정의
- 권한/정책
- 구현 메모

## 2. 전역 셸

모든 화면은 Conductor `AppShell`로 감싼다.

- `topBar`: `C-001 AppTopBar` — 제품명, `C-010 OmniSearchInput`, 시퀀스 공간 선택기, 사용자 메뉴
- `nav`: `C-002 LeftNavPanel` — Conductor `NavList` 기반
- `skipLinkLabel`: "본문으로 건너뛰기"
- `mainId`: `main-content`

## W-001 통합 검색

### 화면 목적

사용자가 가진 식별자 또는 조건으로 PR·커밋·릴리스를 찾고, 결과를 필터·정렬·집계한다. 이 제품의 기본 진입 화면이다.

### 진입 경로

- 애플리케이션 루트 `/`
- TopBar 옴니 검색에서 후보 2건 이상 또는 자유 텍스트 해석
- W-006 그룹·구간 클릭 (질의 문자열 전달)
- W-008 저장된 검색 실행
- 딥링크 `/search?q=<질의>&sort=<키>&cursor=<커서>`
- 상세 화면에서 뒤로가기: 상세로 이동할 때 원본 입력을 **`from_q`**로 남긴다 (CR-019, DEV-078). `q`를 쓰지 않는 이유는 상세 URL에 `q`가 있으면 그 화면이 검색 결과인 것처럼 읽히기 때문이다

### 권한/정책

- 인증 필요. 미인증 요청은 OIDC로 리다이렉트한다 (FR-AUTH-001).
- 결과는 서버가 접근 범위를 강제 결합한 것만 표시한다. 클라이언트는 접근 범위 필터를 조작할 수 없다 (FR-AUTH-002).
- 내보내기는 감사 기록 대상이며 실행 전 대상 건수를 확인 다이얼로그로 표시한다 (FR-SRCH-012, FR-AUTH-004).

### 구현 메모

- 질의 문자열이 URL의 단일 진실이다. 필터 레일 조작은 질의 문자열을 갱신하고, 질의 문자열 변경이 조회를 유발한다. 두 방향의 상태를 따로 두지 않는다.
- 목록 조회와 패싯 조회는 하나의 API 응답으로 받되, 레일은 **세 경우를 구분해 표시한다** (CR-019, DEV-076): `facets` 키가 **없으면** "아직 세지 않음"(WP-032 전), `facets_omitted: true`면 "이번 조회에서 생략", 있으면 분포. 어느 쪽이든 **조용히 비우지 않는다**.
- 시퀀스가 **아직 계산되지 않은 것**(WP-021 전, 값이 `null`)은 `not_computed`로 그린다. 미머지(`unassigned`)로 그리면 화면이 거짓을 말한다 (CR-019, DEV-077).
- 결과 행의 시퀀스 배지는 시퀀스 공간(저장소·브랜치)을 툴팁으로 표시한다. 서로 다른 공간의 시퀀스 값을 나란히 보여줄 때 비교 가능한 값으로 오인되지 않도록 공간이 다르면 배지 색조를 `neutral`로 낮춘다.
- 7자 미만 hex 입력은 서버 호출 없이 클라이언트에서 즉시 `error_prefix_too_short` 안내를 띄운다 (FR-SRCH-004 AC-2).

## W-002 PR 상세

### 화면 목적

PR 1건의 전체 맥락 — 커밋 집합, 시퀀스 위치, 선행·후행, 포함 릴리스, 관계 — 을 한 화면에서 확인하고 다음 조사 단계로 이동한다.

### 진입 경로

- 옴니 검색 해석 결과 (유형 `pull_request`)
- W-001 결과 행 클릭
- W-003 "소속 PR" 클릭
- W-004 범위 결과 행 클릭
- 딥링크 `/pr/:owner/:repo/:number`

### 레이아웃 구조

```text

│ owner/repo #1234 · feat: 결제 재시도 로직          [GHE에서 열기 ↗] │

├──────────────────────────────────┬──────────────────────────────────┤
│ 개요                             │ 선행·후행 (시퀀스 기준)          │
│  대상/소스 브랜치, 라벨, 리뷰어  │  1339 fix: ...                   │
│  변경 규모, 리드타임, 리뷰 대기  │  1340 chore: ...                 │

├──────────────────────────────────┼──────────────────────────────────┤
│ 관계                             │ 포함 릴리스                      │

│  체리픽 → release/2.4 b81f...    │  build-20260820-01  08-20 09:30  │
```

### 권한/정책

- 접근 범위 밖 PR은 HTTP 404로 응답하며 화면은 `not_found` 상태를 표시한다. 존재 여부를 노출하지 않는다 (FR-AUTH-002 AC-4).
- 상세 조회는 감사 기록 대상이다 (FR-AUTH-004).

### 구현 메모

- 헤더·개요·커밋은 진입 시 함께 조회한다. 관계·동시 변경은 섹션 확장 시 조회한다 (IA 원칙 4, 점진적 공개).
- 미머지 PR은 `W-002-NEIGHBORS`를 비활성 상태로 렌더링하고 "머지 후 시퀀스가 부여됩니다"를 표시한다. 섹션 자체를 숨기지 않는다 — 숨기면 사용자가 기능 부재로 오인한다.
- `epoch_stale` 상태에서는 헤더 아래에 Conductor `Banner`(tone `warning`)로 "시퀀스가 재채번되어 이전에 인용한 범위는 무효합니다"를 표시한다. **다만 지금은 도달할 수 없어 만들지 않는다** (CR-020, DEV-087) — 시퀀스가 WP-021까지 전부 `null`이고 에폭 변경을 감지할 경로도 정해져 있지 않다. WP-021이 시퀀스를 채울 때 감지 경로와 함께 정한다.
- 관계 항목의 신뢰도는 `exact`/`derived`/`heuristic` 세 단계를 배지로 구분하고, `heuristic`은 근거 문자열을 항상 함께 표시한다.
- 딥링크의 `:number`는 **앞자리 0이 없는 양의 정수**만 받는다. 그 밖(`abc`, `0`, `007`, `-1`, 소수)은 조회하지 않고 `not_found`를 보인다 — `007`을 받아 주면 URL과 다른 PR(`#7`)을 그리게 되고, 조사 결과를 URL로 인용하는 제품에서 그것은 치명적이다. **문구는 접근 범위 밖과 같아야 한다** — 다르게 말하면 존재 여부를 가르는 신호가 된다 (FR-AUTH-002 AC-4).

## W-003 커밋 상세

### 화면 목적

커밋 SHA 하나에서 소속 PR, 시퀀스 위치, 포함 릴리스, 관계로 이어지는 역추적 경로를 제공한다.

### 진입 경로

- W-002 커밋 목록 항목 클릭

### 권한/정책

- W-002와 동일한 접근 범위 규칙을 적용한다.

### 구현 메모

- `no_sequence` 상태는 PR head 브랜치의 원본 커밋에서 정상적으로 발생한다. 오류가 아니라 "이 커밋은 대상 브랜치에 직접 존재하지 않고 머지 커밋 X로 반영되었습니다"라는 설명과 머지 커밋 링크를 제공한다.
- **`no_sequence`는 시퀀스 값이 아니라 역할로 판정한다** (CR-021, DEV-092). `merge_seq`가 WP-021까지 모든 커밋에서 `null`이라 값만 보면 머지 커밋까지 "체인 밖"이 된다. `role === 'source_commit'`은 **정의상** first-parent 체인 밖이고(squash merge에서 원본 커밋은 브랜치에 직접 착지하지 않는다), 이는 시퀀스 없이 지금 말할 수 있는 사실이다. `merge_commit`인데 `merge_seq`가 `null`인 것은 **미채번**이고 다른 문구를 쓴다.
- **머지 커밋 링크는 소속 PR의 `merge_commit_sha`로 만든다** — API-SRCH-002가 그 키를 싣는다 (CR-021, DEV-091). 미머지 PR이면 키가 없고, 그때는 링크 대신 PR로 가는 길만 준다.
- **`reason_code: 'no_pull_request'`를 "직접 푸시"라고 부르지 않는다** (CR-021, DEV-093). 그것은 "투영이 아직 PR 번호를 잇지 못했다"이고, 직접 푸시는 `role: 'direct_push'`다 — 후자는 WP-021 전까지 도달하지 않는다(DEV-061).
- SHA 표시는 기본 12자 축약, 클릭 시 전체 40자 툴팁, 복사 버튼은 항상 전체 40자를 복사한다. **복사 실패도 알린다** (CR-021, DEV-096).

## W-010 GitHub Command Center

> CR-005 신규. GitHub Operations Plane의 진입점이며 전 capability의 fallback 화면이다.

### 화면 목적

capability manifest에 있는 모든 명령을 검색하고, 생성된 폼으로 구성하고, 실행될 argv를 확인한 뒤 실행한다. 업무 전용 화면(W-011~W-019, W-022)이 다루지 않는 나머지가 전부 여기로 온다.

### 진입 경로

- 좌측 내비게이션 → GitHub Operations
- 업무 화면의 "고급 옵션으로 열기"
- W-021 실행 이력의 "동일 구성으로 다시 실행"

### 섹션

| 섹션 | 내용 | 관련 FR |
| --- | --- | --- |
| GitHub 컨텍스트 | 호스트, 조직, 저장소, 브랜치, 인증된 GitHub 신원. 어느 GitHub에 무엇을 하는지 항상 보인다 | FR-GH-008 |
| Capability 검색 | 명령·설명·카테고리·읽기/쓰기·위험도로 필터. 미지원·차단 항목도 사유와 함께 표시 | FR-GH-001, FR-GH-011, FR-GH-013 |
| Command 폼 | manifest에서 생성. positional과 flag를 타입별 컨트롤로 표현. 제약 위반을 즉시 표시 | FR-GH-003 |
| 실행 미리보기 | 유효 대상, 위험도, 필요 권한과 보유 여부, 비밀이 가려진 argv | FR-GH-002, FR-GH-009 |
| **유효 실행 컨텍스트** (CR-008, C-062) | 실행 직전 확정된 값 — 호스트, GitHub 신원, 조직, 저장소, 브랜치/ref, workspace, gh 버전, manifest 버전, 위험도, 필요 권한, 실제 권한 판정, 정책 판정. 실행기가 환경으로 주입하는 컨텍스트(`GH_HOST`, `GH_REPO` 등) 때문에 미리보기와 실제 대상이 갈리지 않음을 여기서 확인한다. 비밀 값은 표시하지 않는다 | FR-GH-002, FR-GH-008, FR-GH-011 |
| 실행 결과 | 상태, 표준 출력·오류 스트리밍, 구조화 JSON, 아티팩트, 취소. 출력은 무해화 경계를 통과한 것만 표시한다 (C-063) | FR-GH-006, FR-GH-007, NFR-010 |

### 상태

`empty`(capability 미선택), `loading`, `constraint_error`, `permission_denied`, `policy_blocked`, `unsupported_host`, `registry_stale`, `awaiting_confirmation`, `awaiting_approval`, `running`, `succeeded`, `failed`, `cancelled`, `timed_out`.

### 규칙

- 실제 토큰과 비밀 값은 argv 미리보기에 절대 노출하지 않는다. `<redacted>`로 표시한다.
- 미리보기 argv와 실제 실행 argv는 같은 구조화 명령 모델에서 파생한다. **argv 빌더는 하나뿐이다** (CR-008, ADR-017).
- 지원되지 않는 capability를 목록에서 숨기지 않는다.
- **폼 검증 규칙은 UI가 소유하지 않는다.** manifest의 의미 제약 모델을 폼·서버가 함께 읽고, 두 판정이 갈리면 실패로 본다 (CR-008, FR-GH-003 AC-8).
- **gh 출력을 원시 HTML로 렌더링하지 않는다.** ANSI CSI·OSC·제어 문자가 무해화된 뒤에만 화면에 닿는다 (CR-008, ADR-018).
- **실행기에서 브라우저 프로세스를 띄우지 않는다.** `--web` 계열은 URL을 돌려주고 사용자의 브라우저가 연다 (CR-008, ADR-019).
