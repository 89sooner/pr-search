# PR Search 화면 플로우 명세서

> 상태: review | 버전: v0.5 | 갱신일: 2026-08-31

## 1. 전환 규칙

- 전환은 사용자의 현재 컨텍스트(질의 문자열, 시퀀스 공간, 스크롤 위치)를 보존해야 한다.
- 실패 전환은 원인, 영향, 복구 경로를 함께 표시해야 한다.
- 모달/드로어/풀스크린 전환은 뒤로가기와 ESC 동작을 정의해야 한다.
- 조사 흐름은 되돌아갈 수 있어야 한다. 상세 화면에서 브라우저 뒤로가기는 직전 결과 목록의 스크롤 위치와 커서 상태로 복귀한다.

### 1.1 오버레이 유형 규칙

| 유형 | 사용처 | ESC | 뒤로가기 | 포커스 |
| --- | --- | --- | --- | --- |
| 다이얼로그(`Dialog`) | 파괴적·비가역 확인(재채번, 일괄 재처리, 저장소 해제, 대량 내보내기) | 취소로 닫힘 | 닫힘(URL 변화 없음) | 열릴 때 첫 포커서블, 닫힐 때 트리거로 복귀 |
| 드로어(`Drawer`) | 보조 정보(필터 상세, 잡 로그, 관계 항목 근거) | 닫힘 | 닫힘 | 동일 |
| 풀스크린 라우트 | 화면 전환(W-001↔W-002 등) | 동작 없음 | 이전 라우트 | 본문 상단 |
| 인라인 확장 | 섹션 접힘/펼침(원본 커밋, 관계 그룹) | 동작 없음 | 동작 없음 | 토글 유지 |

파괴적 확인은 항상 다이얼로그다. 드로어나 인라인으로 처리하지 않는다.

## 2. Deeplink 규칙

모든 화면은 URL만으로 재현 가능해야 한다. 조사 결과를 티켓·메신저에 붙여 공유하는 것이 이 제품의 핵심 사용 방식이기 때문이다.

| 경로 | 화면 | 파라미터 |
| --- | --- | --- |
| `/` | W-001 | - |
| `/search` | W-001 | `q`, `sort`, `order`, `cursor`, `tab` |
| `/pr/:owner/:repo/:number` | W-002 | `section` (앵커 스크롤) |
| `/commit/:owner/:repo/:sha` | W-003 | - |
| `/ranges` | W-004 | `repo`, `branch`, `from`, `to`, `q`(WP-032에서 붙는다), `epoch` |
| `/releases` | W-005 | `repo`, `branch`(선택 필터, 없으면 저장소 전체) — 셸이 소유한 경로다 (CR-030, DEV-157). 선택은 URL에 담지 않는다 |
| `/analytics` | W-006 | `q`, `from`, `to`, `interval`, `groupBy`, `tz` |
| `/graph` | W-007 | `type`, `repo`, `id`, `depth`, `linkTypes` |
| `/saved-searches` | W-008 | - |
| `/repositories` | W-009 | - |
| `/ops/pipeline` | A-001 | - |
| `/ops/repositories` | A-002 | - |
| `/ops/jobs` | A-003 | `type`, `jobId` |
| `/ops/audit` | A-004 | `user`, `action`, `from`, `to`, `cursor` |

딥링크 예외 처리:

- 존재하지 않는 대상: `not_found` 상태. 통합 검색으로 돌아가는 경로를 제시한다.
- 권한 없음: `not_found` 상태로 응답한다. 접근 범위 밖 개체의 존재 여부를 노출하지 않는다 (FR-AUTH-002 AC-4). 단, 미인증이면 `auth_expired`로 구분한다.
- 인증 만료: `auth_expired` 상태. 현재 경로를 보존해 인증 후 복귀한다.
- 미수집 저장소: `not_indexed` 상태. W-009 저장소 개요로 이동하는 경로를 제시한다.
- 시퀀스 에폭 불일치(`/ranges`의 `epoch` 파라미터가 현재 에폭과 다름): `epoch_stale` 상태. 현재 에폭으로 재조회하는 액션을 제시하고, 자동 재조회는 하지 않는다.

## FLOW-000 진입과 인증

1. 사용자가 임의 경로로 진입한다.
2. 시스템이 세션을 확인한다.
3. 세션이 없으면 현재 경로를 `state`에 담아 OIDC 인가 엔드포인트로 리다이렉트한다.
4. 인증 성공 시 세션을 발급하고 접근 범위를 조회한다.
5. 접근 범위 조회에 실패하면 `permission_unavailable` 상태를 표시하고 재시도 경로를 제공한다. 부분 결과를 표시하지 않는다.
6. 성공 시 원래 경로로 복귀한다.

관련 요구사항: FR-AUTH-001, FR-AUTH-002, FR-AUTH-003

## FLOW-001 옴니 식별자 해석

이 제품의 가장 중요한 흐름이다. 사용자는 손에 있는 문자열 하나를 붙여넣고, 시스템이 그것이 무엇인지 판단한다.

```text
[사용자 입력] → [클라이언트 사전 판정] → [해석 API] → 분기
                       │                        │
                       │ 7자 미만 hex           ├─ 후보 1건 (commit)  → W-003
                       └→ error_prefix_too_short├─ 후보 1건 (pr)      → W-002
                                                ├─ 후보 1건 (release) → W-005
                                                ├─ 후보 2건 이상      → W-001 ambiguous
                                                ├─ 유형 text          → W-001 전문 검색
                                                └─ 후보 0건           → W-001 empty_no_result
```

1. 사용자가 TopBar 옴니 입력에 문자열을 제출한다.
2. 클라이언트가 형태를 사전 판정한다. 7자 미만 hex 문자열은 서버 호출 없이 즉시 안내한다 (FR-SRCH-004 AC-2).
3. 서버가 해석을 수행하고 후보 배열을 반환한다.
4. 후보가 1건이면 해당 상세 화면으로 이동한다. 이동 전 원본 입력을 URL 쿼리에 남겨 뒤로가기 시 입력이 보존되게 한다.
5. 후보가 2건 이상이면 W-001의 `ambiguous` 상태로 후보 카드 목록을 표시한다. 자동 이동하지 않는다.
6. 후보가 0건이면 `empty_no_result` 상태와 함께 원인 후보(미수집 저장소 / 접근 권한 없음 / 오타)를 제시하고 W-009 저장소 개요 경로를 제공한다.

성공 경로: 3~6단계 모두 p95 200ms 이내 (NFR-001).
실패 경로: 검색 타임아웃(3초) 시 `error_search_timeout` 상태와 저장소 조건 추가 안내.

관련 요구사항: FR-SRCH-001, FR-SRCH-002, FR-SRCH-004

## FLOW-002 SHA에서 원인 PR까지 (SCN-001)

1. FLOW-001로 커밋 상세 W-003에 도달한다.
2. `W-003-PR` 섹션에서 소속 PR을 확인한다.
   - 역할이 `merge_commit`이면 PR 1건이 표시된다.
   - 역할이 `source_commit`이면 소속 PR과 함께 "이 변경은 머지 커밋 X로 대상 브랜치에 반영되었습니다" 안내를 표시하고 머지 커밋으로 이동할 링크를 제공한다.
   - 역할이 `direct_push`면 "PR 없음(직접 푸시)"을 표시하고 시퀀스 위치만 제공한다.
3. 사용자가 PR을 눌러 W-002로 이동한다.
4. W-002에서 선행·후행, 관계, 포함 릴리스로 조사를 이어간다.

예외 흐름:

- 보강 미완료(`enrichment_pending`): PR 연결이 비어 있으면 "수집 중" 상태와 예상 반영 시각을 표시하고 자동 재조회 버튼을 제공한다. 자동 폴링은 하지 않는다.
- 동일 SHA가 2개 이상 PR에 속함(`multi_pr`): 모든 PR을 목록으로 표시하고 사용자가 선택한다.

관련 요구사항: FR-SRCH-002, FR-REL-002, FR-ING-004

## FLOW-003 릴리스 구간 조사 (SCN-002)

```text
[W-005 릴리스 목록] --2건 선택--> [구간 비교] --> [W-004 범위 조사]
                                                      │
[W-002 PR 상세] --"범위로 확장"------------------------┤
[W-003 커밋 상세] --"범위로 확장"----------------------┘
```

1. 사용자가 W-005에서 릴리스 2건을 선택하고 구간 비교를 실행한다. 목록은 저장소 스코프이므로 브랜치가 다른 릴리스도 함께 보이며, 그 조합은 실행 전에 차단된다 (CR-030, DEV-158).
2. 시스템이 두 릴리스를 앵커로 `/ranges?repo=&branch=&from=&to=`에 전달한다. 시퀀스가 작은 쪽이 시작 앵커가 된다. **비교 결과 목록은 W-005가 그리지 않는다** — 목록·패싯·뒤로가기 복귀를 W-004 한 곳에만 둔다.
3. W-004가 앵커를 시퀀스 값으로 정규화하고 반개구간 `(from, to]` 결과를 조회한다.
4. 사용자가 패싯(작성자·팀·라벨·경로)으로 후보를 좁힌다.
5. 결과 행을 눌러 W-002로 이동해 개별 PR을 확인한다.
6. 뒤로가기 시 4단계의 필터 상태와 스크롤 위치로 복귀한다.
7. **구간을 검증한 `release_manager`가 안전 구간 표식을 등록한다** (`range.mark_safe`, FR-SEQ-006). 이것이 이 흐름의 종결 단계다 — 조사의 결과를 조직이 공유하는 사실로 남기는 자리이며, 그 사실이 없으면 다음 사람이 같은 구간을 다시 조사한다. **대상 서수는 3단계가 정규화한 끝 앵커이고 에폭은 그 조회가 답한 현재 에폭이다**: 사용자가 숫자를 따로 입력하지 않는다 (CR-057, DEV-462). 등록 전에 화면은 그 공간의 현재 표식을 이미 읽어 두었으며, 요청은 자기가 본 그 값을 함께 보낸다.

**표식은 흐름의 필수 단계가 아니다.** 6단계까지로 조사가 끝나는 경우가 더 많고, 자격이 없는 사용자는 7단계에 닿지 않는다. 그러나 **문서화된 흐름이 그것을 담지 않으면 구현이 빠뜨린다** — `v0.4`까지 어느 FLOW도 이 상호작용을 담지 않아, 이 문서만 따라 `FLOW-003`을 완주한 구현이 `FR-SEQ-006`을 하나도 만들지 않고 끝날 수 있었다 (DEV-466).

예외 흐름:

- 두 릴리스가 다른 대상 브랜치: `error_space_mismatch`. 비교 실행 전 클라이언트에서 차단하고 브랜치 선택을 요구한다.
- 구간 5만 건 초과: `error_range_too_large`. 앵커 조정 또는 패싯 선행 적용을 안내한다.
- 앵커가 대상 브랜치 first-parent 체인 밖: `error_anchor_not_on_branch`. 해당 커밋의 머지 커밋을 대체 앵커로 제안한다.
- 미머지 PR 앵커: `error_anchor_not_merged`.
- 시퀀스 재채번 중(`sequence_reassigning`): 마지막 확정 값으로 결과를 표시하고 상단에 갱신 중 배너를 띄운다.
- **표식 쓰기 자격 없음**(`no_permission`): 등록 액션을 `blockedReason`과 함께 비활성으로 두되 **현재 표식은 그대로 보인다** — 막히는 것은 쓰기뿐이다 (FR-SEQ-006 AC-3).
- **끝 앵커 미해석**(`marker_target_unresolved`): 등록할 서수가 없으므로 액션을 비활성으로 두고 앵커 해석을 요구한다.
- **저장된 표식의 에폭이 낡음**(`marker_epoch_stale`): 표식을 감추지 않고 무효로 표시한다. 현재 에폭의 같은 서수로 옮겨 읽지 않으며, 옮기는 것은 사용자가 현재 에폭으로 다시 등록하는 행위다 (ADR-007, FR-SEQ-005 AC-4).
- **등록 요청의 에폭이 낡음**: 서버가 `SEQUENCE_EPOCH_STALE`(409)로 거절한다. 현재 에폭으로 다시 조회한 뒤 재등록하며, **자동 재시도하지 않는다.**
- **그 사이 다른 사람이 표식을 옮김**: 서버가 `SAFE_MARKER_CONFLICT`(409)로 거절하고 현재 표식을 함께 준다. 화면은 그 값을 보이고 사용자가 다시 결정한다 — **덮어쓰기를 자동으로 재시도하지 않는다** (CR-057, DEV-464).

관련 요구사항: FR-SEQ-002, FR-SEQ-003, FR-SEQ-004, FR-SEQ-006

## FLOW-004 이분 탐색으로 후보 좁히기 (SCN-003)

1. W-004에서 조사 구간이 확정된 상태로 시작한다.
2. 시스템이 다음 검사 지점(남은 후보 구간의 중앙값에 가장 가까운 실재 시퀀스)을 제시한다.
3. 사용자가 외부(CI, 로컬 빌드)에서 그 지점을 검사하고 결과를 정상 또는 이상으로 표시한다.
4. 시스템이 후보 구간을 갱신하고 새 검사 지점과 예상 잔여 횟수를 제시한다.
5. 남은 후보가 1건이 되면 그 PR을 결과로 표시하고 탐색을 종료한다.

예외 흐름:

- 표시 모순(`bisect_contradiction`): 정상 시퀀스가 이상 시퀀스보다 크면 HTTP 409를 반환한다. 화면은 모순 지점을 표시하고 초기화 경로를 제공한다.
- 탐색 중 시퀀스 재채번 발생: 탐색 상태를 무효화하고 초기화를 요구한다. 이전 에폭 기준 표시를 그대로 사용하지 않는다.
- 이탈 후 재방문: 탐색 상태는 사용자·시퀀스 공간별로 서버에 저장되어 있으므로 이어서 진행한다.

관련 요구사항: FR-SEQ-007, FR-SEQ-005

## FLOW-005 통계에서 근거 목록으로 (SCN-005)

1. 사용자가 W-006에서 기간·그룹 키를 지정한다.
2. 각 패널이 독립적으로 조회된다. 한 패널이 실패해도 나머지는 표시된다.
3. 사용자가 그룹 행, 시계열 버킷, 분포 구간 중 하나를 클릭한다.
4. 시스템이 해당 조건을 구조화 질의 문자열로 변환해 W-001로 이동한다.
5. W-001에서 개별 PR을 확인하고 W-002로 이어간다.

예외 흐름:

- 버킷 400개 초과: `error_too_many_buckets`. 간격 확대를 제안한다.
- 집계 5초 초과: `error_aggregation_timeout`. 기간 축소를 제안한다.
- 표본 20건 미만: `low_sample`. 백분위 대신 원값 목록을 표시한다.
- 100만 건 초과: `approximate`. 근사값 배지를 표시한다.

관련 요구사항: FR-STAT-001, FR-STAT-002, FR-STAT-003, FR-STAT-005, FR-STAT-006

## FLOW-006 관계 추적 (SCN-007)

1. W-002 또는 W-003에서 관계 섹션을 확장한다.
2. 시스템이 유형별 간선을 조회하고 신뢰도 배지와 함께 표시한다.
3. 사용자가 되돌림 또는 체리픽 항목을 눌러 대상 개체 상세로 이동한다.
4. W-007이 활성화된 환경이면 "그래프에서 보기"로 관계 전체를 조망한다.

예외 흐름:

- 참조 추출 미완료(`links_pending`): 참조 그룹에 **"참조 분석 중"**을 표시한다. **그 필드는 FR-REL-003 참조 추출의 완결 상태이지 관계 파생 전체의 상태가 아니다** (CR-041, CR-042 DEV-258) — 되돌림·체리픽·스택은 이미 계산돼 있으므로 그대로 표시한다. 관계 섹션 전체를 가리지 않는다.
- 미해결 참조(대상이 아직 색인되지 않음): 참조 문자열만 표시하고 링크는 비활성으로 둔다.
- 신뢰도 `heuristic` 항목: 근거 문자열을 항상 함께 표시한다. 근거 없이 링크만 보여주지 않는다.
- 되돌림 제목 대조 후보가 2건 이상: **모든 후보를 표시하고 다중 후보임을 밝힌다** (FR-REL-004 예외 처리, CR-042 DEV-261). 하나를 고르면 조사 도구가 자신 있게 틀린 답을 낸다.
- 해제된 스택 의존(`detached`): **숨기지 않고 "해제됨"으로 표시한다** (FR-REL-006 AC-3). 저장 계층이 지우지 않고 보존한 사실이므로 화면도 버리지 않는다.
- 대상 저장소가 접근 범위 밖: 간선·식별자·근거는 표시하고 대상 상세와 이동 링크를 두지 않는다 (THR-034). **사유를 문구로 구분하지 않는다.**
- 체리픽 관계 없음: **"체리픽 관계 없음"이다.** 정상 상태이며 오류로 표시하지 않는다. `patch_id`를 얻지 못한 경우에는 **사유**(`no_mirror` / `blob_fetch_disabled` / `compute_failed`)를 함께 밝힌다 (FR-REL-005 AC-5). **관계가 없다는 사실로 "백포트가 누락됐다"를 추론하지 않는다** — 운영 기본값에서 `blob_fetch_disabled`가 대다수를 차지하는 것이 정상이며(CR-024, DEV-111), 그 추론은 SRS가 승인한 적이 없다 (CR-042, DEV-260).
- 관계·동시 변경 조회 실패: **두 하위 섹션은 독립이다.** 한쪽이 실패해도 다른 쪽과 상세 본체는 유지하고, 실패한 섹션에만 오류와 "다시 시도" 버튼을 낸다.

관련 요구사항: FR-REL-003, FR-REL-004, FR-REL-005, FR-REL-006, FR-REL-007, FR-REL-008

## FLOW-007 수집 지연 대응 (SCN-006)

1. 운영자가 A-001에 진입한다.
2. 단계별 지표에서 지연 원인을 판단한다(대기열 적체 / 보강 지연 / 색인 거부).
3. 실패 대기열에서 실패 이벤트를 조회한다.
4. 원인 해소 후 개별 또는 일괄 재처리를 실행한다. 100건 초과 일괄 재처리는 재확인 다이얼로그를 거친다.
5. 웹훅 자체 누락이 의심되면 조정 스캔을 즉시 실행한다 (FR-ING-011 AC-7).
6. 실행 결과를 **잡으로** 지켜본다 — `queued`·`running`·진행률·종료 상태가 그대로 보인다. **버튼을 누른 사실은 스캔 완료가 아니다.**

예외 흐름:

- 재처리 재실패: 재시도 횟수를 누적하고 실패 대기열에 유지한다. 동일 이벤트 3회 재처리 실패 시 보류 상태로 전환하고 자동 재처리 대상에서 제외한다.
- **조정 스캔이 이미 돌고 있다**: 409와 실행 중 잡 ID를 돌려준다. 주기 실행과 수동 실행은 같은 구현을 지나며 동시에 돌지 않는다 (FR-ING-011 AC-7).
- **`security_officer`가 A-001에 들어온 경우**: `archive_only`이므로 이 흐름의 2~6단계에 해당하는 섹션이 렌더링되지 않으며, 화면은 그 데이터를 **요청하지도 않는다** — 403을 받아 숨기는 방식은 권한 판정을 화면 뒤로 미루는 일이다.
- 검색 엔진 장애: `degraded` 상태. 수집은 대기열에 축적되고 검색만 실패함을 배너로 명시한다.

관련 요구사항: FR-ING-007, FR-ING-011, FR-ADMIN-001, FR-ADMIN-002

## FLOW-008 시퀀스 재채번 (비가역)

1. A-003에서 정합성 점검을 실행한다.
2. 불일치가 발견되면 최초 불일치 시퀀스 값과 저장된 SHA, 실제 SHA를 보고한다.
3. 운영자가 재채번을 실행한다.
4. 시스템이 영향 범위(무효화되는 안전 구간 표식 수, 영향받는 저장된 검색 수, 재채번 대상 커밋 수)를 산출해 확인 다이얼로그에 표시한다.
5. 운영자가 저장소 이름을 직접 입력해 2단계 확인을 완료한다.
6. 시스템이 에폭을 1 증가시키고 불일치 지점 이후를 재채번한다.
7. 재채번 완료 후 알림을 발송하고 감사 기록을 남긴다.

예외 흐름:

- 재채번 중 사용자 조회: 마지막 확정 값과 `sequence_state: reassigning`을 함께 반환한다.
- 재채번 실패: 시퀀스 공간을 `stale`로 두고 경보를 발생시킨다. 부분 재채번 상태로 남기지 않는다.
- 커밋 그래프 접근 불가: 점검을 중단하고 공간 상태를 `unknown`으로 표시한다.
- **확인 문자열 불일치**: 서버가 거절하며 잡을 만들지 않는다. 확인은 잡 생성보다 **먼저** 판정한다 — 뒤에 두면 그 사이에 실패한 요청이 활성 잡을 남긴다.
- **확인 이후의 실패**: 클라이언트가 자동으로 다시 요청하지 않는다. 재채번은 비가역이므로 재시도는 운영자의 명시적 재실행이어야 한다 (CR-055).

관련 요구사항: FR-SEQ-005, FR-ADMIN-003

```text

  │

  ├─ 정책 차단 ──────▶ 차단 사유 표시

  ▼

  ├─ R0 ──▶ 즉시 실행
  ├─ R1 ──▶ 대상·동작 미리보기 → 실행
  ├─ R2 ──▶ 명시적 확인 → 대상 상태 재조회 → 변경됨? ──예──▶ 중단, 새로 고침 안내

  │ 성공
  ▼

  │

  ├─ cancelled ──▶ 취소 표시
```
