**이것은 구현이 아니라 계약을 여는 일이다.** FR-SEQ-005 AC-4가 저장된 검색의 `seq:` 조건을

```bash

```

**정해야 할 것 셋.** (1) 어느 시퀀스 공간의 에폭을 기록하는가 — 질의에 `repo:`가 없으면 접근
범위의 모든 저장소가 대상이고, 여럿이면 공간도 여럿이다. (2) 공간이 여럿일 때 하나만 낡아도
전체를 무효로 보는가. (3) `/search` 응답이 `epoch_stale`을 어떻게 싣는가 — 지금 그 필드는
W-004 계열에만 있고 검색 응답 계약에 없다.

**해법이 저장 계층이 아닐 수 있다.** W-001의 `seq:` 질의는 URL에 담기는 순간 이미 같은 성질을
갖고, 저장된 검색은 그것을 더 오래 보관할 뿐이다 — **조회 계층에서 푸는 길**을 먼저 검토한다.
그 판단이 서기 전에는 열 하나로 임의 해법을 만들지 않는다.
