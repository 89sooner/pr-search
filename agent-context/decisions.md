## DEV-160 (구현 중 발견, CR 불필요) — 판정을 하나로 모았다

포함 판정(`findContainingReleases`)과 마지막 릴리스 판정
(`findLatestReleaseSeq`)이 릴리스의 **저장** `base_branch`·`merge_seq`를
조건으로 썼다. 동기화(JOB-REL-007)가 채번보다 먼저 돌면 그 둘이 NULL인 채
커밋만 체인 위에 있고, 그러면 그 릴리스가 포함 목록에서 통째로 빠진다 —
**이미 배포된 PR이 "미배포"로 보인다.**

앵커 해석은 DEV-149대로 이미 다시 찾고 있었는데 포함 판정만 저장 열을 읽었다.
서수는 언제나 현재 에폭 체인에서 `commit_sha`로 다시 찾도록 통일했고,
`findLatestReleaseSeq`는 `findLatestRelease`에 위임한다.

**CR을 열지 않은 이유**: 문서가 요구한 동작을 코드가 지키지 못한 것이라
문서 변경이 없다. 유형은 `구현 결함`(DEV-107의 선례).

## 서수를 URL 앵커로 넘길 때 — `seq:` 접두는 필수다

`classifyAnchor`(`packages/domain/src/anchor.ts`)는 **맨 숫자를 의도적으로
`ambiguous`로 판정한다** (PR 번호인지 서수인지 시스템이 고르지 않는다).
`from=6&to=8`로 넘기면 W-004가 두 앵커를 모두 해석하지 못해 **조회 버튼이
잠긴 채로 도착한다.** WP-026에서 실제로 낸 결함이고(Codex P1) WP-027의
`neighborRangeHref`도 같은 규칙을 따른다.

서수 `0`은 앵커로 표현할 수 없다(`positiveWithin`이 1 이상만 받는다). 채번된
릴리스가 없는 공간의 미배포 구간이 그 값을 내며, 그때는 **`from`을 싣지
않고** 화면이 "시작은 직접 고르세요"를 말한다.

| 250 | `outgoing`도 라우팅하지 않는다 | 그쪽은 라우팅해도 옳다. 그래도 규칙을 하나로 둔다 — 방향마다 갈리면 다음 사람이 `incoming`에도 "최적화"로 넣고, 그 순간 cross-repo 참조가 조용히 사라진다. 대가는 샤드 12개를 도는 것이며 응답이 `limit + 1`로 묶여 있어 요청 크기에 비례해 커지지 않는다 |
| 251 | 워커의 `StoredLink`를 HTTP DTO로 쓰지 않는다 | `confidence`·`evidence`·`to_repository_id`가 없다. 반대로 워커 타입을 넓히면 조정에 필요 없는 필드를 매 회차 실어 나른다. **사용자 대면 읽기 투영을 따로** 둔다 |
| 252 | `limit` 기본 50·최대 100, `limit + 1`로 `truncated` 판정 | 워커의 `scrollLinks`는 끝까지 읽어 메모리에 모은다 — 조정에는 옳지만(한 페이지만 읽으면 나머지가 영영 조정되지 않는다) 사용자 요청에는 상한이 필요하다 |
| 252 | **오프셋을 만들지 않는다** | 공통 원칙 7 / ADR-010. 커서를 세울 요구사항이 아직 없으므로 상한과 절삭 표시로 답한다. 필요해지면 그때 커서 계약을 연다 |
| 253 | 필터가 **세 번** 걸린다 (앵커 → 간선 → 대상 내용 batch) | 간선이 보이는 것과 대상의 내용이 보이는 것은 다른 판정이다. 저장소를 건너뛰는 참조에서 그 둘은 **다른 저장소**다 |
| 253 | 대상이 범위 밖이면 **내용 필드를 두지 않는다**(키 부재) | `null`로 채우면 "확인했고 없다"가 된다. 그리고 문구가 사유를 구분하면 존재가 샌다 — "권한이 없습니다"도 "대상이 존재합니다"도 존재를 밝히는 문장이다 |
| 253 | `resolved`와 `content_available`은 다른 사실 | 전자는 "대상이 색인되었는가"(FR-REL-003 AC-3), 후자는 "이 요청자가 볼 수 있는가". `resolved: true` + `content_available: false`는 정상이다 |
| 254 | 자격 상태 셋을 **정상 도메인 상태**로 | 미머지 PR에는 `merged_at`이 없어 AC-2의 ±90일 창에 기준점이 없다. `created_at`으로 대체하면 AC-2가 정한 창이 아닌 다른 창을 계산한 뒤 그것을 "자카드 상위 20"이라고 부르게 된다 |
| 254 | 200 판정은 **`changed_files_count`로만** | `files_truncated`는 `MAX_CHANGED_FILES`(3000) 상한의 표식이라 다른 계약이다. `false`에서 "그러니 200 이하"를 추론하면 틀린다 |
| 255 | 자격·교집합·점수를 **Elasticsearch가 함께** 판정 | "후보 N건을 가져와 앱에서 계산해 상위 20"은 진짜 상위 20이 N번째 밖에 있을 수 있고, **그 사실이 응답 어디에도 드러나지 않는다** |
| 256 | 겹치는 경로는 **사전순 앞 10** | AC-5에 순위 개념이 없다. 순서를 정하지 않으면 같은 정본이 다른 응답을 낸다(ADR-004) |
| 257 | C-021 상태를 **섹션 축과 항목 축으로** 가른다 | 하나의 enum에 섞으면 "없는 것 · 모르는 것 · 실패한 것 · 해제된 것"이 같은 빈 화면이 된다 |
| 258 | `links_pending`은 **참조 그룹에만** | CR-041이 "참조 추출의 완결 상태"로 확정했다. 관계 섹션 전체를 가리면 이미 계산된 되돌림·체리픽·스택이 참조 실패 하나 때문에 숨는다 |
| 260 | FLOW-006의 **"백포트 누락 후보" 삭제** | FR-REL-005 어디에도 근거가 없고, 운영 기본이 `blob_fetch_disabled`라 후보 없음이 **정상**이다(CR-024 DEV-111). 화면이 없는 기능을 지어내지 않는다 |
| 261 | 다중 후보는 **응답이 이미 싣는 근거로** 판정 | 같은 `evidence`를 공유하는 `heuristic` 되돌림이 둘 이상이면 그것이 곧 "후보가 여럿"이다. 새 저장 필드를 만들지 않는다 |
| 262 | W-001을 WP-031 관련 화면에 **추가** | 와이어프레임과 `ResultTable.tsx` 주석이 둘 다 "관계 배지는 WP-031 소관"이라 적는데 관련 화면에 없었다. 이월 계약의 누락 정정이지 범위 확장이 아니다 |
| 264 | 요약이 **없는 것**과 관계가 **없는 것**을 가른다 | `null`이면 배지 영역 자체를 그리지 않는다. 빈 배지를 두면 "관계 없음"으로 읽히고, 그것은 아직 확인하지 않은 것을 확인했다고 말하는 것이다 (CR-019 DEV-077과 같은 규율) |
| 265 | 조회 계층을 **`links.ts` 밖에** 둔다 | ADR-008 가드레일의 허용 목록은 **파일 경로**다. 그 파일에 사용자 대면 조회를 넣으면 "요청자가 없다"는 워커용 사유를 그대로 물려받고 검사기가 침묵한다 |
| 265 | 가드레일에 `mget`·`es.get` 추가 | 대상 내용을 붙일 때 **ID를 알고 있으므로** `mget`이 가장 짧은 길인데 강제 필터를 통째로 지나간다. `client.get`은 받지 않는다 — Redis 핸들도 같은 이름을 쓴다 |

**버린 대안**: `reference_key`를 세 계열로 일반화하는 안(CR-041이 이미 기각), 관계 목록에 커서를 세우는 안(요구사항이 없다), `SeverityTag`로 신뢰도를 그리는 안(그 어휘는 **실행 위험도**이고 관계 신뢰도와 다른 축이다 — `heuristic`이 "차단됨"처럼 읽힌다), 대상 내용을 `mget`으로 붙이는 안(THR-034가 막으려는 그 유출이다).

## PR #47 리뷰 P1 — 새 파일이 선례를 따르지 않았다

`searchRelationLinks`가 `assertNoShardFailures`를 부르지 않았다. 샤드가 실패해도 Elasticsearch는 살아남은 것으로 HTTP 200을 주므로 **짧아진 목록이 `truncated: false`와 함께** 나가 화면이 "관계가 이것뿐"이라고 말한다. 라우트는 `PartialSearchError`를 504로 옮길 준비가 돼 있었는데 그 오류가 나지 않았다.

**이 질의가 특히 위험한 이유가 있었다** — 저장소를 건너뛰는 참조를 찾으려고 라우팅을 포기했고, 그것이 샤드 12개를 전부 도는 질의로 만들었다. **내가 내린 결정(DEV-250)이 이 실패 모드의 확률을 올렸는데 그 대가를 계산하지 않았다.**

→ **새 파일을 만들 때 물어라: 이 경로가 다른 경로와 같은 검사를 지나는가.** 앵커·대상·동시 변경·일반 검색·식별자 해석이 전부 지나는 검사였고 빠진 것은 이 하나였다.
